# Limits

| Limit | Why we accept it | What checks it |
|---|---|---|
| **A game, not a job.** Skins make it look like a job, but no run here is real work | A game is the only way to replay the same change for every model and know the ground truth. Epoch makes the same argument for [EBR-bench](../prior/themes.md), a board game it calls a reasonable proxy for learning a job. Ours is a proxy argued the same way | If there is a marked difference in the skins, particularly game vs real narratives |
| **The game is trainable.** The engine is public, so a lab can make unlimited timelines and train on them | A secret engine cannot be rerun or checked, and no secret stops training anyway, see [learning the game](../harness/contamination.md#what-it-does-not-stop). A trained model's score still says how well it reads the game, but no longer that the trait carries to a job | The [recognition check](../pilot/provider-checks.md#recognition), the anchor models on the [trend plots](../harness/models.md#trend-plots), and the stale handoff task in [future](future.md#whether-it-holds-outside-our-game), the one that tells a trained model from one with the trait |
| **A fresh call each round.** The agent remembers what happened, as the full record is in every prompt, but not what it thought | Its own reasoning is the one place a model won't question a claim, and cost grows with the square of the run, see [interface](interface.md#rejected). Each round is a small handoff, which is how long-running agents already work | The [rolling conversation](../pilot/provider-checks.md#rolling-conversation) check runs every model, and the gap is reported per model beside the headline |
| **Tools in the headline.** A model that cannot use a notes file or a sandbox scores lower for it | The trait is reading a change, not reading a CSV, and a deployed agent has both, see [interface](interface.md#tools). Tool use share sits beside every score, so a model that never touched a tool is visible | The [bare harness](../pilot/provider-checks.md#bare-harness) check runs every model without the tools, and the bare gap is reported per model beside the headline |
| **Equal weight across scenarios is a prior.** The headline treats a switch as common as a shock, and a rise as common as a fall. No real setting is known to | A plain mean with equal weights is the simplest prior to state and to reweight, see [scoring](scoring.md#why-a-pool-within-and-a-plain-mean-across). The weakest trait is named beside the headline so one trait cannot hide another | The trait profile is reported beside the headline, so a reader with a base rate can reweight |
| **The stories cut both ways.** Kodak and Peloton are picked with hindsight | They motivate the question. The grounding is the human finding of system neglect, see [people](../prior/people.md#massey-and-wu-2005-system-neglect) | The No change and One shock scenarios sit in the headline, so holding on and jumping both cost |
| **Two skins in the proof of concept.** Two stories are a thin sample of stories, so a model could be good at both and poor at a third | Skin sensitivity is a finding, not an error, and one gap paired by seed already shows whether a story can sway a model, see [spread](scoring.md#spread) | More skins in the full study, each with its own headline and a gap for every pair |
| **No human baseline.** A score compares models with each other, not with people | Comparing models over time needs no human anchor | Not planned for the headline. Massey and Wu's map says which way people err. A [future study](future.md#whether-it-holds-outside-our-game) |
| **The change never reacts to the agent.** Real plans often wear out because they are leaned on | A reactive change muddies the Discerning baseline, the seeds and the error bars | Not planned for the headline. A [future study](future.md#how-the-world-changes) |
| **Switching is free.** A model that never moves still earns most of the output | The scenario score prices it: the Complacent baseline sits near 0.55 where there is a switch, so never moving forfeits nearly half the range. A fee would leak into every trait | The [inertia](scoring.md#extension-inertia) extension, if the pilot still finds the gaps too small to read |
| **The ceiling has zero lag.** The Discerning baseline moves the round a switch lands, which no reader can, so nobody scores 1 where there is a switch | Lag is the thing we want to price. The Perfect baseline would be worse, as it knows the weather too, so part of the gap to it is luck. See [scoring](scoring.md#why-these-two-baselines) | The [Bayesian baseline](baselines.md#the-bayesian-frontier) marks how much of the gap is lag no reader can beat, and the [noise threshold](scoring.md#noise-threshold) says at what noise the lag becomes unavoidable |
