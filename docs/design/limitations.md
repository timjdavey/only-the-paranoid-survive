# Limitations

**What this design gives up, why we accepted each one, and which tier fixes it.**

The benchmark is built in two tiers: a cheap proof of concept first, then a funded full study. "Beyond" means work past the full study, listed in [future work](future.md).

| Limitation | Why we accepted it | How to overcome, and at which tier |
|---|---|---|
| **The first main score tops out at the perfect baseline.** Performance, the proof of concept's main score, stops rising once models get as close to the perfect baseline as inference allows, so it can't be plotted over releases for long | No model will be near it before the full study exists, and one continuous number is what a proof of concept needs. See [Why two tiers](decisions.md#why-two-tiers) | Full study: lead with discernment, the smallest change a model acts on |
| **One kind of change in the proof of concept.** The only change is one unit's pay falling, which a player watching each unit on its own can find. So insight, whether the agent works out what changed, is a weaker test than it will be | It is the one change we already have a Bayesian baseline for, and it takes one paragraph to explain. See [Why a change is a typed event](decisions.md#why-a-change-is-a-typed-event) | Full study: changes to how units affect each other, how fast extra spend stops paying, and which unit gets the credit |
| **No human baseline.** A score says how models compare with each other, not with people | Comparing models over time needs no human anchor, and recruiting people costs time a proof of concept doesn't have | Beyond the full study: human baseline |
| **One reasoning setting per model.** Scores are a lower bound for models that do better with more thinking | Budget. Each model runs at its standard high setting, so the comparison is fair even if it isn't complete | Full study: reasoning sweep |
| **One simulated world.** A model could be good at this game and nothing else | Four skins, the same game dressed as four different stories, widen the surface without the cost of a second game. See [Why four skins over one interface](decisions.md#why-four-skins-over-one-interface) | Full study: one real agentic task with a stale handoff note. Beyond: a second game. See [future work](future.md#whether-it-holds-outside-our-game) |
| **No skin is neutral.** Each story hints at how often things change: a plant suggests stability and a market suggests drift | The abstract skin, with plain letters for names, is the baseline. The fictional skin gives the headline, and how far scores spread across skins is reported as a result | Beyond: test whether the time unit, such as weeks or minutes, or showing outside conditions changes the play |
| **A model may suspect it is being tested.** We can measure this, not remove it | Any extra experimenting it causes costs output in the no-change run, and a scan of the transcripts reports it. See [Why the game is hard to game](decisions.md#why-the-game-is-hard-to-game) | Full study: every transcript read |
| **A small sample.** Twenty seeds, each a fixed set of luck, on a few models | We are aiming to only show the measure works, so model comparisons are early reads | Full study: every model on release, more seeds and more change sizes |
| **The change never reacts to the agent.** Real plans often wear out because they are leaned on, and real units pay out late | A change that reacts to the agent muddies the no-change run, the Bayesian baseline and the error bars. See [Why the change is not reflexive](decisions.md#why-the-change-is-not-reflexive) | Beyond: changes that react to the agent, and units that pay out weeks later |
| **The agent reads its past rather than living it.** [Schubert et al.](../prior/past-in-the-prompt.md#schubert-et-al-2024-asymmetric-belief-updating) suggest a past a model lived through biases it more | The record gives every model the same past, and keeps the cost to one briefing and the 40 live rounds. See [Why the agent writes its own notes](decisions.md#why-the-agent-writes-its-own-notes) | Beyond: a full live run, where the agent plays from round 1 with no record |
| **The record shows a style of play.** The agent may copy how much the past player experimented | Its author is the Bayesian baseline, so it experiments the right amount, and the pilot measures how much the style sways the agent. See [Why the record comes from a baseline](decisions.md#why-the-record-comes-from-a-baseline-and-its-style-is-a-factor) | Beyond: vary how much the record experiments |
| **Switching is free and can be undone at once** | A wrong split still loses output every round it stands, and with only 40 rounds, time spent wrong is costly. See [Why no lock-in](decisions.md#why-no-lock-in) | Beyond: make switching cost something, and vary how much |
| **Our simulated world could set a false target.** The scores lean on the true levels in our own simulation | The backup catch rate reads only the agent's own shares, and every skin runs in the pilot | Full study: a check against one real task. Beyond: steps towards more realistic tasks, and a second game |
